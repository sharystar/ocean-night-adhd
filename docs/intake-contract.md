# 海洋收件箱：事项拆分与配鱼契约

这份契约用于保证“把今天一股脑说完”时，系统不会为了概括主题而漏掉独立事项。

## 先拆事情，再配鱼

1. 每个可以被单独完成、发送、等待或照顾的结果，生成一枚鱼卵。
2. 同一种事情可以生成多枚同类鱼卵；鱼种不是去重条件。
3. 只有共享同一交付物的连续动作才合并。例如“做同一份 PPT、翻译、补 evidence”是一件事。
4. 外来委托、自己的研究、沟通和情绪照护永远不互相吞并。
5. 无法分类的事项仍然各自生成绿海龟，不允许被丢弃。
6. 系统输出前必须检查：识别出的独立事项是否全部有对应鱼卵。

## 稳定的海洋伙伴

| 事项类型 | 海洋伙伴 |
| --- | --- |
| 外来委托 | 鹦鹉鱼 |
| 关系与沟通 | 宽吻海豚 |
| 自己的研究写作 | 椰子章鱼 |
| 文献阅读 | 河豚 |
| 汇报与会议 | 鲸鲨 |
| 数据分析 | 萤火鱿 |
| 行政杂务 | 招潮蟹 |
| 身体照料 | 港海豹 |
| 生活杂务 | 太阳海星 |
| 情绪照护 | 海獭 |
| 尚未识别 | 绿海龟 |

## 验收例子

- “写摘要、跑模型、报销、预约牙医、给妈妈回电话”必须生成 5 枚鱼卵。
- “修改摘要、写方法、回复审稿意见”必须生成 3 枚章鱼蛋，不能去重成 1 枚。
- “导师让我做 PPT、还要翻译、补 evidence；推进自己的文章；催导师；我很内耗”应生成 4 枚鱼卵，而不是 6 枚碎片或 1 枚主题蛋。
